# Проверка Samsung Tizen — 2026-10-11 / 2026-10-12

Версия: KinoWatch 0.2.2. Устройство: UE43TU7090UXRU, Tizen 5.5.
Это Samsung порт MIT KPuppy. Ниже зафиксированы результаты разработки
и подготовки первого публичного выпуска.

## Автоматические проверки

- Итоговый полный прогон: 56 файлов, 683 теста — прошли.
- TypeScript и production build прошли.
- Платформа, AVPlay, SamsungPlayerScreen и useAuth — ESLint без ошибок.
- Samsung CSS — stylelint без ошибок.
- Полный ESLint: пять прежних ошибок в Bookmarks, Category, Collections и History.
- Полный CSS lint: 11 ошибок и 37 предупреждений в неизменённом CSS исходного
  клиента. Glob исправлен для Windows. Отдельные стили каталога, включая flex
  gap, требуют дальнейшего визуального тестирования.

Новые тесты проверяют последовательность подготовки/запуска/перемотки AVPlay,
миллисекунды, паузу при смене качества, отмену устаревших событий, скрытие полных
ссылок из ошибок, продление таймера при прогрессе и предел 120 секунд, разбор
SRT/VTT, запасные ссылки выбранного качества, обновление ссылок без очистки
каталога, повтор после обрыва, сохранение позиции, предел двух повторов и Back.

## Физический телевизор

Подписанный пакет установлен и запущен через Samsung TV SDK и локальный профиль сертификата.
Пользователь подтвердил экран входа по коду и работу каталога после входа.
Чёрный экран первой сборки устранён полифиллом globalThis и defer стартового
скрипта для Chromium 69.

На выбранном пользователем видео 720p:

- HLS: первый прогресс примерно через 22 секунды, буфер 99%, но нет READY.
  Увеличение таймера само по себе зависание не устранило.
- HLS2: NOT_SUPPORTED_FORMAT; HLS4: CONNECTION_FAILED.
- MP4: prepare завершился примерно через 17.6 секунды; PLAYING, длительность
  8700.746 секунды. Пользователь подтвердил картинку и звук.
- Примерно через 79 секунд PLAYING произошёл CONNECTION_FAILED. Установки
  в этот момент не было. Причина в соединении/CDN пока не установлена.
- MP4 с продолжением от 78 секунд завершил prepare, но завис на seek в READY
  перед play. Теперь seek выполняется в PLAYING после первого сигнала времени.
- Пользователь подтвердил, что Home работает. Пакет KinoWatch1 успешно закрыт
  командой SDB `shell 0 kill KinoWatch1` по просьбе пользователя.
- Перенос seek в PLAYING не устранил проблему MP4: через ~34 секунды
  TypeMismatchError. Пользователь сообщил о вылете приложения.
- MP4 при отсутствии HLS4 идёт через HTML media element без вызовов AVPlay. Metadata и
  playing получены через ~18 секунд, позиция 78 секунд, но затем пользователь
  сообщил MEDIA_ERR_DECODE (3). В тот момент клиент запрашивал HEVC;
  кодек самого MP4 не был независимо проверен.
- Для клиента Samsung применяются `supportHevc=0`, `supportHdr=0`, HLS4 при
  наличии такой опции. Сервер сохраняется. Перед получением ссылок ожидается
  применение этих настроек. Новая миграция имеет отдельный локальный маркер.
  Media-links сбрасываются только при изменении настроек устройства сервиса.
- Сервис подтвердил AVC в HLS manifest (`avc1.640028,mp4a.40.2`), но браузерный
  MP4 продолжал возвращать MEDIA_ERR_DECODE при восстановлении позиции.
  Кодек MP4 по одному HLS manifest доказать нельзя. Причина сбоя MP4 пока
  не установлена. Основной путь изменён на AVC HLS4 через AVPlay.
- AVC HLS4: prepare завершился за ~12.2 секунды, затем PLAYING. Перемотка
  на сохранённую позицию 138 секунд завершилась за ~4.8 секунды. Пользователь
  подтвердил картинку, звук и продолжение с сохранённого места: «Да, всё играет».
  За следующие четыре минуты диагностический журнал не зарегистрировал новых
  ошибок. Отсутствие ошибок в журнале само по себе не доказывает непрерывный
  просмотр; длительное воспроизведение ещё не проверено.

Подтверждены запуск и восстановление позиции для AVC HLS4 на выбранном видео.
Длительный стабильный просмотр и автоматическое восстановление после обрыва
пока не подтверждены на устройстве.

Итоговый подписанный пакет 0.2.2 собран без `KINOWATCH_DIAGNOSTICS_URL`.
Адрес временного диагностического сервера отсутствует в production bundle;
лицензии и подписи включены в `.wgt`.
Пакет 0.2.2 установлен поверх предыдущей версии и успешно запущен через SDK.
Временный диагностический сервер на компьютере остановлен. Подтверждение
пользователя о 720p и продолжении относится к предшествующей диагностической
сборке с тем же выбором AVC HLS4. После установки итоговой сборки пользователь
также подтвердил воспроизведение 4K.

2026-10-12: пользователь сообщил «я 4K проверил, всё работает» на том же
UE43TU7090UXRU. Это подтверждает воспроизведение выбранного 4K-видео.
Диагностика в этой сборке отключена: кодек, битрейт, частота кадров и
длительность 4K-просмотра отдельно не зафиксированы. Продолжение с
сохранённого места в 4K отдельно не проверено.

В следующем сообщении пользователь подтвердил 720p, 1080p и 4K, работу
звука и переключение аудиодорожек без проблем. Это проверка выбранных
потоков и дорожек на указанной модели; кодеки новых потоков не измерялись.

## Не подтверждено на физическом ТВ

Совместимость всех 4K-файлов и комбинаций видео- и аудиокодеков, HDR,
внешние и встроенные субтитры,
автопереход к следующей серии, Live TV, длительный просмотр, работа после
выключения компьютера и полный обход каталога. Реализация и модульные тесты
не считаются доказательством этих возможностей на устройстве.

## Подготовка к публичному выпуску

2026-10-12: инструкции установки, управления и совместимости оформлены для
других владельцев. Персональные пути SDK, IP и профиль сертификата удалены
из исходников; скрипты принимают явные параметры или локальные переменные
окружения. Полный прогон после подготовки: 683 теста, 56 файлов — прошли.
TypeScript и production build прошли; JS bundle сохранил тот же хеш имени
`index-COWxf4ZU.js`, код воспроизведения при этой подготовке не менялся.

Публичный build ZIP содержит неподписанный dist, инструкции и скрипты.
Проверены содержимое, SHA256 и отсутствие личных сертификатов/подписей/
диагностического адреса. Подпись из распакованного ZIP с `-SkipBuild`
успешна без установки node_modules и запуска npm build. На телевизор эта
тестовая подпись повторно не устанавливалась.

CI workflow разобран как YAML; удалённый GitHub Actions ещё не запускался.
Автоматическая проверка файлов исходников и относительных Markdown-ссылок
прошла. На момент этой подготовки публичный репозиторий и GitHub Release
ещё не были созданы.
